# Lifecycle Middleware

## What is Middleware?

Middleware lets you **hook into the lifecycle of every agent run** — before it starts, after it finishes, or when it fails. Think of it like Express.js middleware, but for AI agent executions.

**Common use cases:**

- Logging every run's start time, agent name, and duration
- Sending performance metrics to Datadog, Prometheus, or CloudWatch
- Recording errors to Sentry or other error tracking tools
- Validating or auditing inputs/outputs for compliance

---

## Defining Middleware

Use the `middleware()` factory function and register it with `Runner`:

```typescript
import "dotenv/config";
import { middleware, Runner } from "ezagent";

const timingMiddleware = middleware({
  name: "performance_timer",

  // Runs BEFORE the agent starts (use agentName, NOT agent.name)
  before: async ({ runId, agentName }) => {
    console.log(`[Timer] Starting run ${runId} for agent "${agentName}"`);
  },

  // Runs AFTER the run completes successfully (has durationMs and result)
  after: async ({ runId, agentName, durationMs }) => {
    console.log(`[Timer] Run ${runId} (${agentName}) finished in ${durationMs}ms`);
  },

  // Runs if the run throws an error (has durationMs and error)
  onError: async ({ runId, agentName, error }) => {
    console.error(`[Timer] Run ${runId} (${agentName}) failed: ${error.message}`);
  }
});

// Register middleware with the Runner
const runner = new Runner({
  middleware: [timingMiddleware]
});
```

---

## Execution Order

- **`before` hooks**: Run in **declaration order** (first to last), BEFORE any LLM call or guardrail check.
- **`after` hooks**: Run in **reverse order** (last to first), AFTER the run completes successfully.
- **`onError` hooks**: Run in **reverse order** if an error occurs. Failures inside `onError` are safely isolated — they never hide the original error.

---

## Context Properties Available Per Hook

| Hook      | Available Properties                                             |
| --------- | ---------------------------------------------------------------- |
| `before`  | `runId`, `agentName`, `mode`, `sessionId?`, `signal`, `metadata` |
| `after`   | All `before` properties + `result`, `durationMs`                 |
| `onError` | All `before` properties + `error`, `durationMs`                  |

> **Important**: The context provides `agentName` (a string), **not** an `agent` object. If you need agent-level details inside middleware, use the `agentName` string to look it up in your own registry.

---

## Attaching Middleware to a Single Agent via Plugins

Middleware registered on `Runner` applies to **all agents** that run through it. To attach middleware only to a specific agent, use a [Plugin](./plugins) instead:

```typescript
import { plugin, middleware, Agent, OpenAIProvider } from "ezagent";

const auditPlugin = plugin({
  name: "audit",
  middleware: [
    middleware({
      name: "audit_hook",
      before: ({ runId, agentName }) => console.log(`[Audit] ${agentName} starting run ${runId}`)
    })
  ]
});

const agent = new Agent({
  name: "SecureAgent",
  instructions: "Handle sensitive requests.",
  model: "gpt-4.1-mini",
  provider: new OpenAIProvider({ apiKey: process.env.OPENAI_API_KEY! }),
  plugins: [auditPlugin] // Only this agent gets the audit middleware
});
```
