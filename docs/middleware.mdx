# Lifecycle Middleware

Middleware hooks allow developers to intercept execution before a run begins, after a run finishes, or when a run throws an error.

---

## Defining Runner Middleware

Use the `middleware()` function:

```typescript
import { middleware, Runner } from "ezagent";

const timingMiddleware = middleware({
  name: "performance_timer",
  before: async ({ runId, agent }) => {
    console.log(`[Timer] Starting run ${runId} (${agent.name})`);
  },
  after: async ({ runId, durationMs }) => {
    console.log(`[Timer] Run ${runId} finished in ${durationMs}ms`);
  },
  onError: async ({ runId, error }) => {
    console.error(`[Timer] Run ${runId} encountered error: ${error.message}`);
  }
});

// Register middleware with Runner
const runner = new Runner({
  middleware: [timingMiddleware]
});
```

---

## Execution Order

- **`before` Hooks**: Executed in **declaration order** (forward) BEFORE input guardrails or LLM calls.
- **`after` Hooks**: Executed in **reverse declaration order** (onion model) AFTER the run completes successfully.
- **`onError` Hooks**: Executed in **reverse declaration order** if an error occurs. Failures inside `onError` hooks are safely isolated so they never mask the primary run error.

---

## Context Parameters

| Hook      | Parameter Context                            |
| --------- | -------------------------------------------- |
| `before`  | `{ runId, agent, mode, signal }`             |
| `after`   | `{ runId, agent, mode, result, durationMs }` |
| `onError` | `{ runId, agent, mode, error, durationMs }`  |
