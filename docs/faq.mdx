# Frequently Asked Questions

Common questions, architecture choices, and design rationale behind EzAgent.

---

### 1. Does EzAgent wrap external frameworks like LangChain or AutoGen?

**No.** EzAgent is a clean, zero-dependency, provider-neutral TypeScript SDK built natively from the ground up. It gives you full visibility into execution logic without hidden magic.

---

### 2. Can I use custom or local LLM models (e.g. Anthropic, Ollama)?

**Yes!** Implement the `Provider` interface (`chat()` and `stream()` methods) and pass your custom provider instance to `Agent`.

---

### 3. How does retry logic work?

EzAgent automatically retries transient, non-streaming network and rate-limit errors (HTTP 429, 500, 502, 503, 504) using exponential backoff with jitter. Visible text streams are not retried mid-stream to prevent output token duplication.

---

### 4. Is `FileStorage` safe for production multi-process apps?

`FileStorage` uses atomic file replacement suitable for single-node / single-process services. For distributed multi-instance infrastructure, implement a custom `StorageAdapter` backed by Redis, PostgreSQL, or MongoDB.

---

### 5. How are multi-agent handoff loops prevented?

EzAgent maintains a `visitedAgents` registry for each run and enforces a `maxHandoffs` cap (default: 5). If a cycle or excessive delegation is detected, `Runner` throws a `HandoffError`.
