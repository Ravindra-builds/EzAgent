# Long-Term Factual Memory

While **Sessions** retain full conversation turn history, **Memory** dynamically retrieves specific relevant facts (e.g. user preferences, corporate policies, account details) and injects them into the prompt before calling the LLM.

---

## Memory vs. Sessions

| Feature       | Sessions                                               | Memory                                      |
| ------------- | ------------------------------------------------------ | ------------------------------------------- |
| **Purpose**   | Retain sequential turn-by-turn conversation transcript | Store discrete factual snippets             |
| **Lifecycle** | Loaded on every turn for a specific `sessionId`        | Retrieved on-demand based on a search query |
| **Storage**   | Sequential list of ChatMessage objects                 | Searchable index of MemoryRecord items      |

---

## Using `InMemoryMemory`

`InMemoryMemory` stores facts and uses lexical matching to retrieve relevant items:

```typescript
import { Agent, InMemoryMemory, OpenAIProvider, Runner } from "ezagent";

// 1. Initialize the memory store
const memoryStore = new InMemoryMemory();

// 2. Save facts into a namespace
await memoryStore.save({
  namespace: "user_preferences",
  content: "User prefers concise answers written in bullet points."
});

await memoryStore.save({
  namespace: "user_preferences",
  content: "User works as a Senior TypeScript Developer."
});

// 3. Configure Agent to use memory
const agent = new Agent({
  name: "PersonalizedAgent",
  instructions: "Help the user with technical questions.",
  model: "gpt-4.1-mini",
  provider: new OpenAIProvider({ apiKey: process.env.OPENAI_API_KEY! }),
  memory: {
    adapter: memoryStore,
    namespace: "user_preferences"
  }
});

// 4. Run agent with a memory search query
const runner = new Runner();
const result = await runner.run(agent, {
  input: "How should I structure my new project?",
  memory: {
    query: "preferences developer" // Retrieves relevant facts
  }
});

console.log(result.output);
```

---

## Memory Injection in Prompts

When memory facts are retrieved:

1. `Runner` queries `memory.adapter.search(query)`.
2. `Runner` formats retrieved facts into an ephemeral `system` message.
3. The LLM receives the relevant facts as system context _without_ adding them permanently to the session conversation history.
